# aki_sys 手动部署手册(手敲版)

> **这份文档写给"不想跑脚本、要自己掌控每一步"的场景** —— 服务器初始化、产物上传、启动、验证、发版、回滚,全部是可以直接复制粘贴的命令。
>
> 一键自动化方式(`deploy.ps1` / `bootstrap.ps1`)见 `deploy/README.md`。两份文档描述的是同一套流程,只是执行方式不同。
>
> 当前仓库状态:后端 Spring Boot 3.4.4(Java 17)+ 前端 Vue 3(Vite)+ MySQL 8 + Redis,systemd 管后端、nginx 托管静态文件并反代 `/api`。

---

## 0. 先看清"东西最终落在哪"

部署的本质就是把本地构建产物搬到服务器固定位置,再让 systemd 和 nginx 去用它们。

```
本地                                    服务器
────────────────────────────────────    ────────────────────────────────────────────
backend/target/aki-admin-1.0.0.jar  →   /opt/aki-admin/aki-admin.jar      (systemd 启动它)
frontend/dist/ 里的内容(不是这层目录) →  /opt/aki-admin/web/               (nginx 的 root)
deploy/aki-admin.env.example        →   /etc/aki-admin/aki-admin.env      (权限 600)
deploy/aki-admin.service            →   /etc/systemd/system/aki-admin.service
deploy/nginx.conf                   →   /etc/nginx/conf.d/aki-admin.conf
sql/init.sql                        →   导入 MySQL(建库 + sys_user/sys_role)
sql/homepage_init.sql               →   导入 MySQL(个人主页 7 张 site_* 表)
```

| 服务器上的角色 | 值 |
|---|---|
| 运行服务的系统用户 | `aki`(nologin 系统账号,不给登录) |
| 应用目录 | `/opt/aki-admin`(jar 与 web 都在这) |
| 配置目录 | `/etc/aki-admin`(`aki-admin.env`,权限 600 root:root) |
| 日志目录 | `/var/log/aki-admin`(应用日志 + heap dump) |
| 对外访问 | nginx 80 → `/` 静态文件、`/api/` 反代 `127.0.0.1:8080` |

## 1. 前置条件

**服务器**
- Ubuntu 20.04+ / Debian 11+ / CentOS 8+ 均可,1 核 2G 起步(Java 内存上限按 512M 配的)
- 安全组 / 防火墙放行 **22、80、443**;**3306 与 6379 绝对不要对公网开放**
- 能 SSH 登录(手动部署用密码登录也完全可以,不需要免密)

**本地(本机已具备,版本仅供参考)**
- JDK 17、Maven 3.6+、Node 18+

## 2. 本地:构建产物

```powershell
cd C:\myproject\aki_sys
.\stop-all.bat                 # 必须先停!本地后端进程会锁住 jar,Maven 无法覆盖
                               # 若它显示"未在运行"但 jar 仍被锁:

mvn -B -DskipTests clean package
cd ..\frontend
npm install                    # 首次才需要
npm run build
cd ..
```

**验证点**
- `backend\target\aki-admin-1.0.0.jar` 存在,约 44 MB(含全部依赖)
- `frontend\dist\index.html` 和 `frontend\dist\assets\` 存在

## 3. 服务器:初始化(装环境 + 建库建表 + 装配置)

这一步只做一次。手动做分两小步。

### 3.1 把 `deploy/` 和 `sql/` 传上去(**必须保持兄弟目录关系**)

`server-init.sh` 是按 `<脚本目录>/../sql` 去找 SQL 的,层级错了它就找不到、也不会建表。

```powershell
$IP = "你的服务器IP"        # 后面所有命令都用这个变量

ssh root@$IP "rm -rf /tmp/aki-deploy && mkdir -p /tmp/aki-deploy/deploy /tmp/aki-deploy/sql"
scp -r deploy/* root@${IP}:/tmp/aki-deploy/deploy/
scp -r sql/*    root@${IP}:/tmp/aki-deploy/sql/
```

### 3.2 执行初始化

```powershell
ssh root@$IP "bash /tmp/aki-deploy/deploy/server-init.sh"
```

脚本会依次做这 11 件事:

| # | 步骤 | 做什么 |
|---|---|---|
| 1 | 识别系统并安装依赖 | apt/yum 装 OpenJDK17、MySQL、Redis、nginx |
| 2 | 安装 Java 17 | 老系统官方源没有就改走 Adoptium(Temurin) |
| 3 | 创建用户与目录 | `aki` 用户 + `/opt/aki-admin`、`/etc/aki-admin`、`/var/log/aki-admin` |
| 4 | 配置并启动 MySQL | 启动 + 开机自启 + 建库建表 |
| 5 | 配置并启动 Redis | 启动 + 开机自启 |
| 6 | 安装 nginx | 装包 + 处理既有默认站点 |
| 7 | 安装 nginx 与 systemd 配置 | 把 `nginx.conf`/`aki-admin.service`/`env` 模板装到位 |
| 8 | 防火墙 | ufw 或 firewalld 放行 ssh/http/https |
| 9 | 部署用户免密 sudo | 写 `/etc/sudoers.d/aki-deploy`(先校验后安装) |
| 10 | 生产配置检查 | 检查 `CHANGE_ME` 占位符 |
| 11 | 初始化完成 | 打印下一步指引 |

> **这一步要几分钟**(apt 装包),属于正常。

**几个真实会遇到的坑**

- **建库账号需要跑两遍**:第一次跑的时候 `/etc/aki-admin/aki-admin.env` 还是 `CHANGE_ME`,脚本会跳过创建 `aki` 这个数据库账号(它不肯用占位符当密码)。填完密码后**再跑一次同一个脚本**即可对齐(脚本是幂等的)。
- **Ubuntu 18.04 等老系统**:官方源没有 `openjdk-17`,脚本会自动改从 Adoptium 装;`apt update` 若因 EOL 报 404 会自动把源切到 `old-releases.ubuntu.com`。
- **CentOS/RHEL**:新装的 `mysql-server` 会给 root 一个临时密码(写在 `/var/log/mysqld.log`),免密连不上。此时脚本**跳过建库但会继续完成其余初始化**,并打印提示。拿到密码后重跑:
  ```bash
  MYSQL_ROOT_PASSWORD='你的root密码' bash /tmp/aki-deploy/deploy/server-init.sh
  ```
- 接管 80 端口前,脚本会把现有 nginx 站点整体备份到 `/root/aki-nginx-backup-<时间戳>/`。

**验证点**

```bash
ssh root@$IP "systemctl is-active mysql redis-server nginx"     # 三个都是 active
ssh root@$IP "ls -ld /opt/aki-admin /etc/aki-admin /var/log/aki-admin; ls -l /etc/aki-admin"
# env 文件应为 -rw------- 600 root root

# 表结构(init.sql 建 2 张,homepage_init.sql 建 7 张,共 9 张)
ssh root@$IP "mysql --default-character-set=utf8mb4 -u root -p -e 'USE aki_sys; SHOW TABLES;'"
```

期望看到:`sys_user`、`sys_role`,以及 `site_profile`、`site_skill`、`site_project`、`site_post`、`site_timeline`、`site_message`、`site_visit`。

> 如果只有前两张,说明 `homepage_init.sql` 没被导入。手动补:
> `mysql --default-character-set=utf8mb4 -u root -p < /tmp/aki-deploy/sql/homepage_init.sql`
> 它是幂等的(`CREATE TABLE IF NOT EXISTS`),随便重复执行。
>
> 反过来,`sql/init.sql` **含 `DROP TABLE IF EXISTS`**,只适合空白库,已有数据时绝对不要重跑。

## 4. 服务器:填生产配置

```bash
ssh root@$IP "vi /etc/aki-admin/aki-admin.env"
```

必须改的:

| 变量 | 说明 |
|---|---|
| `AKI_DB_PASSWORD` | 数据库密码。**只能用字母、数字和 `. _ @ # % ^ + = -`**;禁用空格、`: / ?`、`\ $ ' "` 和中文。推荐 `openssl rand -hex 24` 生成 |
| `AKI_REDIS_PASSWORD` | Redis 密码。**服务器 Redis 默认没有 `requirepass`,所以这里默认留空就好**;只有你给 Redis 设了密码才填,并保证两处一致 |
| `AKI_JWT_SECRET` | init 脚本已自动填了随机值,确认不是 `CHANGE_ME` 即可 |

为什么密码字符集卡这么死:这个值要同时穿过 **systemd 的 EnvironmentFile 解析**、**JDBC URL 拼接**和 **shell/SQL 字面量**三层。`\` 和 `$` 会被 systemd 转义或展开,密码会被悄悄改写,表现为"明明填对了却连不上"。

> 不需要做 URL 编码:`@` 是允许字符,写成 `%40` 反而对不上。

改完**重跑一次初始化脚本**,让它用新密码创建/对齐 `aki` 库账号:

```powershell
ssh root@$IP "bash /tmp/aki-deploy/deploy/server-init.sh"
```

**验证点**(用 env 里的密码试连,能进说明账号已就绪)

```bash
ssh root@$IP "mysql --default-character-set=utf8mb4 -u aki -p -e 'USE aki_sys; SHOW TABLES;'"
```

## 5. 本地:上传产物并启动

### 5.1 后端 jar

```powershell
scp backend\target\aki-admin-1.0.0.jar root@${IP}:/tmp/aki-admin.jar

# 先留一份上一版用于回滚,再原子替换
ssh root@$IP "cp -f /opt/aki-admin/aki-admin.jar /opt/aki-admin/aki-admin.jar.bak 2>/dev/null; install -o aki -g aki -m 644 /tmp/aki-admin.jar /opt/aki-admin/aki-admin.jar && rm -f /tmp/aki-admin.jar && ls -l /opt/aki-admin/aki-admin.jar"
```

> 文件名必须是 `aki-admin.jar`:systemd unit 的 `ExecStart` 写死了 `/opt/aki-admin/aki-admin.jar`。
> 首次部署时该文件还不存在,`cp` 那句会失败,用 `2>/dev/null` 忽略即可。

### 5.2 前端 dist

```powershell
# 打包 dist 里的内容(注意末尾的 . ,打的是内容而不是目录本身)
tar -czf dist.tar.gz -C frontend\dist .
scp dist.tar.gz root@${IP}:/tmp/aki-web.tar.gz

ssh root@$IP "tar -tzf /tmp/aki-web.tar.gz >/dev/null && sudo tar -xzf /tmp/aki-web.tar.gz -C /opt/aki-admin/web && rm -f /tmp/aki-web.tar.gz && sudo chown -R aki:aki /opt/aki-admin/web && ls /opt/aki-admin/web"
```

**两个坑**
1. **先校验再解包**(上面 `tar -tzf >/dev/null` 那句)。**不要**先 `rm -rf /opt/aki-admin/web/*` 再解包 —— 一旦包损坏或磁盘满,目录已经空了,nginx 立刻整站 404 且无法回滚。稳妥做法是解到 `web.new` 再 `mv`。
2. 解包的是 `dist/` 里**内容**,如果多包了一层,nginx 的 root 下就会多出一个 `dist/` 目录,页面 404。

### 5.3 启动服务

```powershell
ssh root@$IP "systemctl daemon-reload && systemctl restart aki-admin && sleep 6 && systemctl status aki-admin --no-pager"
```

首次部署如果 unit 还是新装的,顺手设为开机自启:

```powershell
ssh root@$IP "systemctl enable aki-admin"
```

## 6. 验证(逐层往上查)

下面这组命令**在服务器上执行**(先 `ssh root@<你的服务器IP>` 登进去)。写成 bash 而不是 `ssh root@IP "..."` 一行流,是因为里面带 JSON 引号,在 PowerShell 里转义很容易出错。

```bash
# 1) 后端进程本身(未登录返回业务错误码属正常,只要不是连接被拒)
curl -i -s http://127.0.0.1:8080/api/auth/me | head -20

# 2) 登录接口能否拿到 token
curl -s -X POST http://127.0.0.1:8080/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"admin123"}'
# 期望: {"code":200,"msg":"登录成功","data":{"token":"...","user":{...}}}

# 3) nginx 是否在服务静态文件
curl -I http://127.0.0.1/

# 4) 日志
journalctl -u aki-admin -n 60 --no-pager      # 启动报错看这里
tail -n 50 /var/log/aki-admin/aki-admin.log   # 应用日志
```

然后浏览器打开 `http://<服务器IP>/`:

| 路径 | 期望 |
|---|---|
| `/` | 公开主页(蓝色渐变 Hero + 项目/文章/时间线等入口) |
| `/projects`、`/posts`、`/timeline`、`/message`、`/about` | 建设中占位页(阶段 1-3 才填真实内容) |
| `/admin` | 未登录会跳到登录页;用 `admin / admin123` 登录后进控制台 |

> ⚠️ **这个项目所有错误都是「HTTP 200 + 业务码」**,所以排查时不要只看 HTTP 状态码,要看响应体里的 `"code"`。例如路径不存在返回的是 `{"code":404,"msg":"接口不存在: ..."}`,HTTP 状态是 200。
>
> ⚠️ **登录后第一件事就是改掉 `admin/admin123`**,否则等于把后台送人。

## 7. 后续发版(手动)

初始化只需一次,之后每次发版就是"重新构建 → 上传 → 重启":

```powershell
cd C:\myproject\aki_sys
.\stop-all.bat

cd backend;  mvn -B -DskipTests clean package; cd ..
cd frontend; npm run build; cd ..

# 后端
scp backend\target\aki-admin-1.0.0.jar root@${IP}:/tmp/aki-admin.jar
ssh root@$IP "cp -f /opt/aki-admin/aki-admin.jar /opt/aki-admin/aki-admin.jar.bak; install -o aki -g aki -m 644 /tmp/aki-admin.jar /opt/aki-admin/aki-admin.jar && rm -f /tmp/aki-admin.jar && sudo systemctl restart aki-admin"

# 前端(只发前端时跳过上面两段)
tar -czf dist.tar.gz -C frontend\dist .
scp dist.tar.gz root@${IP}:/tmp/aki-web.tar.gz
ssh root@$IP "tar -tzf /tmp/aki-web.tar.gz >/dev/null && sudo tar -xzf /tmp/aki-web.tar.gz -C /opt/aki-admin/web && rm -f /tmp/aki-web.tar.gz && sudo chown -R aki:aki /opt/aki-admin/web"
```

**回滚**

```bash
ssh root@$IP "sudo cp -f /opt/aki-admin/aki-admin.jar.bak /opt/aki-admin/aki-admin.jar && sudo systemctl restart aki-admin"
```

前端回滚要在本地留上一版 `dist.tar.gz` 重新上传(nginx 侧没有版本目录)。

## 8. 排查手册(按症状查)

| 现象 | 原因与处理 |
|---|---|
| 登录报 `table doesn't exist` / 表不存在 | 建表没成功。`SHOW TABLES` 看看是缺 2 张还是缺 7 张:缺 7 张 = `homepage_init.sql` 没导入;全缺 = `init.sql` 没跑或 SQL 目录层级传错了 |
| 后端日志 `Access denied for user 'aki'` | env 里的密码与数据库里的不一致。**重跑一次 `server-init.sh`** 即可对齐(它会对已存在账号执行 `ALTER USER`) |
| 服务起不来,`journalctl` 里是数据库连接失败 | `/etc/aki-admin/aki-admin.env` 密码没改或不对 |
| `systemctl status` 报 `Unable to access jarfile` | unit 里 `ExecStart` 的路径与 `/opt/aki-admin/` 下实际文件名不一致(必须是 `aki-admin.jar`) |
| `systemctl` 报 unit 无效 / 未知指令 | unit 里用了 systemd 高版本专属语法。注意 `StandardOutput=append:` 需要 systemd ≥240(CentOS 8 是 239、Ubuntu 18.04 是 237 都不支持),本仓库当前版本已改用 journald |
| 页面能打开但接口全 404 | nginx 的 `proxy_pass` 末尾多写了 `/`(末尾带斜杠会吃掉 `/api` 前缀)。正确写法是 `proxy_pass http://127.0.0.1:8080;` |
| 刷新 `/admin/...` 白页或 404 | nginx 缺 SPA 回退。`location / { try_files $uri $uri/ /index.html; }` 不能删(前端用 `createWebHistory()`) |
| 白屏、控制台报 assets 404 | `index.html` 被浏览器缓存了。确认 `location = /index.html` 的 `no-cache` 还在,然后强刷 |
| 页面中文显示成 `杩愯惀浜哄憳` 这类乱码 | 导入 SQL 时没带 `--default-character-set=utf8mb4`(UTF-8 字节被按 GBK 解读后二次编码)。用 `sql/fix_mojibake.sql` 就地修复,以后导入都带上该参数 |
| 日志里中文乱码 | systemd unit 里那三个 UTF-8 启动参数被删了。JDK 17 在 locale 为 `C/POSIX` 的服务器上会让 `System.out` 退化,必须保留 `-Dfile.encoding=UTF-8`(实测确认:JDK 17 上 `System.out` 的编码回退到 `defaultCharset()`,而它由 `file.encoding` 决定) |
| 登录后立刻掉线 / 请求 401 | Redis 连不上或密码不一致。后端要求 Redis 中存在该 token(`AuthInterceptor`),Redis 重启清空后所有人都要重新登录 |
| 8080 端口被占 | `ss -lntp \| grep 8080` 看是谁。改 `AKI_PORT` 后记得同步 nginx 的 `proxy_pass` |
| Maven 报 `Unable to rename ... .jar.original` | 本地后端进程锁着 jar,先 `.\stop-all.bat` |

## 9. 这份手册对应的仓库状态

**当前已修复(2026-09,提交 `3c1baa7`)**
- `deploy.ps1` 上传 SQL 到 `/tmp/aki-sql`,而 `server-init.sh` 是以 `sudo bash <绝对路径>` 执行的、CWD 不变,导致四条查找路径全部落空 → **首次部署静默不建表**。已改为把 `sql/*.sql` 一并放进脚本同目录
- `server-init.sh` 原本**只导入 `init.sql`**,7 张 `site_*` 表要手工补。已改为自动导入 `homepage_init.sql`(幂等)
- `DB_EXISTS` 查询失败不再被当成"库不存在"(否则可能在已有数据的库上跑含 `DROP TABLE` 的 `init.sql`)
- MySQL 密码改用 `MYSQL_PWD` 传递,不再出现在进程命令行
- sudoers 改为先校验后安装
- `aki-admin.service` 去掉 `StandardOutput=append:`(systemd ≥240 才有)
- `nginx.conf` 放行 `/.well-known/acme-challenge/`(否则 certbot 签发失败)、`gzip_types` 补 `text/javascript`

**已知未修(手动流程基本不受影响)**

| 问题 | 影响谁 |
|---|---|
| `deploy.ps1` 健康检查只等 3 秒且只 curl 一次 | 脚本流程:Spring Boot 冷启动常 >3s,会假失败并跳过前端上传,造成新 jar 配旧 dist |
| `deploy.ps1` 的 `set -euo pipefail` 让启动失败时的诊断块永不执行 | 脚本流程:只剩一句"远程执行失败(退出码 1)",看不到 `journalctl` |
| `deploy.ps1` 按"谁监听 8080"盲杀本地进程 | 脚本流程:8080 上是别的项目会被误杀 |
| `server-init.sh` 的 `apt-transport-https` 在 Debian 13 已移除 | 装依赖阶段可能整脚本退出,手动装依赖不受影响 |
| `bootstrap.ps1` 的 scp 缺 `BatchMode`、Redis 失败被吞仍写 env 等 | 只用 `bootstrap.ps1` 时 |
| `nginx.conf` 缺 `listen 80 default_server`;安全响应头被注释且 `add_header` 不继承 | 同机有其他站点时 |

## 10. 上 HTTPS(可选,建议做)

```bash
ssh root@$IP "apt install -y certbot python3-certbot-nginx && certbot --nginx -d 你的域名"
```

`certbot` 会自动改写 nginx 配置、加 443 监听并配置自动续期。签完把 `nginx.conf` 末尾那三行安全响应头取消注释(`X-Content-Type-Options` / `X-Frame-Options` / `Referrer-Policy`)。

> 注意:`add_header` 在 nginx 里**不会被 location 继承**。`/assets/` 和 `= /index.html` 两个 location 各自有 `add_header`,所以 server 级别的安全头对它们不生效 —— 需要那三个头覆盖所有路径时,得在每个 location 里重复写一遍。

**数据库备份**(建议顺手配上)

```bash
mysqldump --default-character-set=utf8mb4 -u root -p aki_sys > /root/backup-$(date +%F).sql
```
