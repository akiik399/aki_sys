# aki_sys → 个人主页 改造计划

> 定位：**公开作品集（游客可看）+ 登录后的内容管理后台（自己用）**
> 技术路线：**保留 Spring Boot 3 + MySQL + Redis + Vue3 全栈**（复用登录态与 RBAC）
> 内容板块：个人简介 / 技能+项目 / 博客文章 / 经历时间线 / 留言板 / 访客统计

---

## 一、核心思路：一套代码，两个前台

不新建项目、不重写。把现有系统"降级"为后台，在前面加一个公开站点：

```
游客 ──► 公开站点（SiteLayout，无需登录）
              │  只读接口 /api/public/**
              ▼
      同一套 Spring Boot + MySQL + Redis
              ▲
              │  JWT + Redis 校验，写接口 /api/**
你   ──► 管理后台（AdminLayout，沿用现有登录）
```

**两个必改的开关（先改这两个，其余才有意义）：**

| 文件 | 现状 | 要改成 |
|---|---|---|
| `frontend/src/router/index.js:44-53` | `if (!token && to.path !== '/login') return '/login'` —— 除登录页外全拦 | 改成 `meta.public: true` 白名单：只有管理区路由才要求 token |
| `backend/.../config/WebConfig.java:22-26` | 只放行 `/api/auth/login` | 追加放行 `/api/public/**`（只读），其余 `/api/**` 照旧校验 |

## 二、数据模型（新增 7 张表，`sys_user` / `sys_role` 不动）

新建 `sql/homepage_init.sql`，沿用 `init.sql` 的写法（`SET NAMES utf8mb4`、utf8mb4_unicode_ci、`created_at/updated_at` 规范）。

| 表 | 关键字段 | 说明 |
|---|---|---|
| `site_profile` | nickname, avatar, slogan, bio_md, location, email, social_json | **单行表**（id=1），首页 Hero 数据源 |
| `site_skill` | name, category, level(0-100), icon, sort, status | 技能条 |
| `site_project` | title, summary, cover, tech_json, repo_url, demo_url, highlights_md, featured, sort, status | 作品集；`featured` 决定是否上首页 |
| `site_post` | title, slug, summary, content_md, cover, tags_json, status, published_at, views | 博客；`status` 区分草稿/发布 |
| `site_timeline` | type(edu/work/project), title, org, start_date, end_date, description, sort | 经历时间轴 |
| `site_message` | nickname, email, content, ip, ua, status, reply, replied_at | 留言；`status` = 待审/通过/拒绝 |
| `site_visit` | path, ip, ua, referer, session_id, created_at | 访问明细，统计靠聚合查询 |

设计取舍：
- **标签先用 `tags_json` 内嵌**，不要一上来拆 `site_tag` 表——数据量小，拆表只增加联表成本。
- 所有内容表统一带 `status` 字段，管理端和公开端共用一张表，靠 `status` 过滤。
- 索引：`site_post(slug)` 唯一、`site_visit(created_at)`、`site_visit(session_id)`、`site_message(status)`。

## 三、后端改造（沿用现有分层：entity / mapper / service / controller / dto）

**新增（公开只读，`PublicXxxController`，走 `/api/public/*`）**
- `GET /api/public/profile` —— 个人资料
- `GET /api/public/projects?page=&size=` / `GET /api/public/projects/{id}`
- `GET /api/public/posts?page=&tag=` / `GET /api/public/posts/{slug}`
- `GET /api/public/timeline`、`GET /api/public/skills`
- `POST /api/public/messages` —— 游客留言（唯一公开的写接口）
- `POST /api/public/visit` —— 埋点

**新增（管理端，`AdminXxxController`，走 `/api/admin/*`，需登录）**
- profile 编辑、各内容表 CRUD（分页/排序/上下架）、留言审核与回复、访问统计聚合

**可直接复用的现成能力**
- `common/Result.java`、`common/GlobalExceptionHandler.java` —— 统一返回与异常
- `security/JwtUtil.java`、`AuthInterceptor.java`、`UserContext.java`、`RedisKeys.java` —— 鉴权链路
- `config/MybatisPlusConfig.java` —— 分页插件，列表接口直接用
- `service/SysUserService.java` —— CRUD 写法模板，照抄结构即可

**需要真正写新逻辑的三处**
1. **留言防刷**：`@Valid` 参数校验 + Redis 限流键 `aki:rate:msg:{ip}`（Redis 已就绪，`INCR` + `EXPIRE` 即可）+ 隐藏蜜罐字段（机器人会填，人会漏）。
2. **文章浏览量**：Redis `INCR aki:pv:post:{id}` 扛读，定时任务或阈值触发回写 MySQL，别每次访问都 `UPDATE`。
3. **访问埋点**：建议放在**后端过滤器**而不是前端上报（前端埋点会被广告拦截器挡掉，且能伪造）。过滤爬虫 UA、同 `session_id` 按 UV 去重。

## 七、风险与注意点

1. **路由守卫**是最容易漏的一步：不改白名单，公开站点永远是登录页。
2. **必须 sanitize**：留言内容和 Markdown 文章都来自输入，`v-html` 前过 `dompurify`。
3. **统计会被爬虫污染**：过滤 UA 黑名单、同 IP 去重、UV 按 `session_id` 而非 IP 算。
4. **Redis 键要分前缀**：`aki:login:`（现有）、`aki:rate:`（限流）、`aki:pv:`（计数），避免和登录态互相 `KEYS` 干扰、也便于单独设 TTL。
5. **上线前收紧安全**：`WebConfig` 现在的 `allowedOriginPatterns("*")` + `allowCredentials(true)` 组合不能带到生产；JWT 密钥（`aki.jwt.secret`）必须换掉并走环境变量。
6. **别过度设计**：不需要引入 Spring Security 全套、不需要 Elasticsearch 全文检索、不需要评论盖楼和用户注册。这个站点的目标是"展示你"，内容管理够用就行。
